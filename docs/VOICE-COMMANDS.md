# Голосовые команды через JSON (без пересборки)

Прокси `alice-voice-proxy` грузит команды из
`/data/opt/spotify-connect/voice-commands.json` на старте. Правь JSON и
перезапускай прокси — **пересборка не нужна**. Исходник конфига в репозитории:
[voice-commands.json](voice-commands.json).

## Как работает распознавание

Текст от ASR сперва нормализуется (нижний регистр, `А-Я/Ё → а-я/ё`, обрезка
хвостовой пунктуации) и с него снимаются `activation_prefixes` (обращения к
ассистенту в начале фразы). Затем по порядку:

1. **`exact`** — точное совпадение всей фразы (после снятия префикса).
2. **`regex`** — POSIX ERE, байтовый (Кириллица работает). Текст уже в нижнем
   регистре, так что пиши паттерны строчными. Если в `action` есть `{1}`, туда
   подставляется число секунд, найденное в фразе (перемотка на N секунд).
3. **Поиск** — `search.verbs` (`включи `…) или `search.music_prefixes`
   (`песню `…) → остаток уходит в Spotify-поиск. Фильтры:
   `search.question_words` (вопросы) и `search.home_words` (умный дом) → команда
   игнорируется и уходит нативной Алисе.

Первое совпадение побеждает: все `exact`, потом все `regex`, потом поиск.

## Действия (`action`)

Транспорт понимает прокси: `__PAUSE__`, `__RESUME__`, `__NEXT__`,
`__PREVIOUS__`, `__CLEAR_QUEUE__`, `__SEEK_START__`, `__SEEK_END__`,
`__SEEK_FORWARD__`, `__SEEK_BACK__`, `__SEEK_FORWARD_<сек>`,
`__SEEK_BACK_<сек>`. Любой другой `action` без `__…__` трактуется как
поисковый запрос (крошка/текст). Новое действие требует поддержки в C —
для простых фраз используй существующие.

Ещё действия (не транспорт, но обрабатываются так же, без поиска):
`__LIKE__`, `__FAVORITES__`, `__NOW_PLAYING__`, `__HISTORY_BACK__`,
`__BLACKLIST_ARTIST__`, `__BLACKLIST_TRACK__`, `__REBOOT__`.

### Перезагрузка

`__REBOOT__` («алиса, перезагрузись», «перезагрузи колонку», «перезапустись» …,
только точные фразы) — Алиса говорит «перезагружаюсь» (её собственный ответ
глушится), музыка на паузу, через 12 с `sync; reboot`. В первые 120 с после
загрузки команда отказывает («я только что перезагрузилась») — чтобы повторно
услышанная фраза не зациклила колонку.

### Группа / исполнитель

«включи группу X», «поставь исполнителя X», «песни группы X», «включи певицу X»
(и без «включи»: «группа X», «хочу послушать группу X») — запрос помечается
`@artist X` и ищется по ИСПОЛНИТЕЛЮ, не по названию трека. Пометка держится и
когда Алиса назвала цель («Включаю: Ska-P.» → `@artist ska-p`; из «Включаю: X,
песня «Y»» берётся только X). Существительные — `artist_noun()` в прокси.
`alice-spotify-search.sh` находит самого артиста (тот, кто на большинстве треков
`artist:X`: «дельфин» → Dolphin; иначе поиск артистов с совпадающим именем: «ska
p» → Ska-P, «5 diez» → #####) и играет только его треки; если в фразе есть ещё
слова («группа Disturbed sound of silence») — первой ставится эта его песня.
Артиста с таким именем в Spotify нет → обычный поиск по фразе.
Тёзки (2026-11-19: «стая» — на Spotify Стая, СтаЯ, С.Т.А.Я., Стая FAM): сначала
берётся исполнитель, которого ты уже слушал (`radio-source`, `radio-artists.txt`)
с этим именем буква в букву; если найденный по трекам совпадает только без точек
и дефисов — побеждает исполнитель с точным именем. Если поиск забит тёзками,
треки берутся из альбомов самого исполнителя (и радио делает так же). Проверить
выбор, ничего не включая: `SEARCH_DRY=1 alice-spotify-search.sh "@artist стая"`.

### «Ты поставила не то»

«Алиса, ты поставила не то», «что за дичь ты включила», «это не то», «не та
песня», «я просил другое» (`__WRONG__`) — Алиса говорит «сейчас поищу другое»
(`replies.wrong_retry`) и `alice-wrong-pick.sh` ищет твою последнюю просьбу
заново — твоими словами, а не по анонсу Алисы, — исключив то, что играет:
трек, его исполнителя, альбом (`SEARCH_NOT`). Неправильный трек убирается из
истории воспроизведения и поисков монитора, а его исполнитель — из прошлых
исполнителей радио (иначе он вернулся бы случайным треком). Просьбы не было
или она старше 3 часов — «не помню, что ты просил» (`replies.wrong_unknown`).

### Альбом

«включи группу кино альбом группа крови», «поставь альбом группа крови группы кино»,
«исполнителя земфира альбом вендетта», «альбом звезда по имени солнце» — прокси
помечает запрос `@album Y|X` (Y — альбом, X — исполнитель, может не быть). Если
Алиса сама ответила «X, альбом «Y»», это тоже альбом. `alice-spotify-search.sh`
находит исполнителя так же, как для «группу X», берёт его альбом с самым похожим
названием (иначе — поиск альбомов), выключает перемешивание и включает альбом с
первого трека до конца. Радио при этом останавливается: после альбома ничего не
добавляется. Альбома нет — играет исполнитель, как на «группу X».
Проверить выбор, ничего не включая: `SEARCH_DRY=1 alice-spotify-search.sh "@album группа крови|кино"`.

### Ответы Алисы (`replies`)

Что Алиса говорит за нас («повтори за мной …»): «что играет», «на паузе …»,
«ничего не играет», чёрный список, «перезагружаюсь», «я только что
перезагрузилась». Для каждой ситуации — список вариантов в разделе `replies`,
каждый раз берётся случайный, один и тот же подряд не повторяется; пустой список —
фраза по умолчанию. Подстановки: `{track}` («исполнитель, название»), `{artist}`,
`{title}`. Слова «включи», «играет», «песня», «трек» рядом с названием не
ставить — Алиса примет фразу за музыкальный запрос. Правится в мониторе: 🎙 →
вкладка «Ответы».

### Что играет дальше (очередь)

Голосовой запрос включает только первый трек; дальше — `alice-radio.sh`:
- «включи группу X» → дальше треки X; «включи песню X» и выбор в мониторе → дальше
  исполнитель этой песни; «включи избранное» → дальше избранное.
- За 10 с до конца трека в очередь Spotify ставится столько, чтобы впереди было
  **2** трека. Добавленное с телефона учитывается и играет первым.
- Порядок случайный, сыгранное за сутки не повторяется (live/remaster той же
  песни — тоже повтор). Явный запрос песни играет её всегда.
- Треки исполнителя кончились → каждый следующий случайный: из избранного или
  исполнитель из прошлых запросов. В «Голосовых запросах» монитора: «X: всё
  сыграно — дальше случайные треки».
- «дальше» — следующий из очереди или сразу из радио; «назад» — то, что играло
  до этого. «пауза» / «продолжи» радио не сбрасывают.
- «очисти очередь» (2026-11-19) — Алиса говорит «начинаю чистить очередь,
  подождите окончания» (пустая очередь — «очередь и так пустая»), затем
  `alice-queue-drain.sh` пропускает треки очереди по одному (~1 с на трек,
  музыка всё это время на 0), возвращает прежний трек на прежнее место и Алиса
  говорит «я всё очистила» (или «очистила не всё, осталось N»). Радио остаётся:
  у конца трека оно снова поставит 2 своих. Фразы — `replies.clear_*`.
- Телефон включил плейлист/альбом → радио выключается, играет выбранное.

### Чёрный список

`__BLACKLIST_ARTIST__` («добавь группу/исполнителя в чёрный список», «заблокируй
исполнителя») — исполнитель играющего трека (первый из указанных); если в фразе
есть имя («добавь группу Кино в чёрный список») — ищется в Spotify по имени.
`__BLACKLIST_TRACK__` («добавь трек/песню в чёрный список», просто «в чёрный
список») — играющий трек. Обе команды стоят ПЕРВЫМИ в `commands`, иначе фраза с
названием группы уйдёт в поиск. «из чёрного списка» / «в чёрном списке» их не
вызывают (паттерны требуют «в чёрный список»).

Добавляет и пропускает `alice-blacklist.sh` (список —
`receiver-state/blacklist.txt`, строки `kind\turi\tname\tepoch`). Алиса отвечает
«X теперь в чёрном списке» (её собственный ответ глушится, как в «что играет»).
Дальше: поиск и «избранное» не включают и не ставят в очередь треки из списка
(в журнале ⛔ «не включаю — в чёрном списке»); `alice-auto-advance.sh` тихо
пропускает такой трек, если он всё же заиграл (из очереди, с телефона) —
обнаружение до ~2 с, музыка на время пропуска на 0. Удалять записи — панель
«Чёрный список» в мониторе (✕).

## Пример добавления команды

```json
{ "action": "__NEXT__", "exact": ["вперёд трек", "мотай дальше"] }
```

или regex:

```json
{ "action": "__SEEK_FORWARD_{1}", "regex": ["^промотай вперёд на [0-9]+ секунд"] }
```

## Редактор в мониторе (🎙)

Кнопка 🎙 рядом с ⚙ на странице монитора (`http://<ip>:28088/`):

- **Проверь фразу** — поле сверху: показывает, что сделает прокси с фразой
  (команда / поиск исполнителя / поиск / «ответит Алиса»). Это приближение в
  браузере (JS RegExp), но порядок тот же: точные фразы → шаблоны → поиск.
- **Команды** — карточки; в каждой точные фразы и шаблоны (regex) чипами:
  ✕ убрать, поле «+ …» и Enter — добавить. Фраза, которая уже есть в другой
  команде, не добавится. Метки «изменено» / «новая» и кнопка «↺ Как было по
  умолчанию» — против `voice-commands.default.json`. Внизу — новая команда:
  из списка действий или «Включить музыку по фразе…» (действие = что включить,
  как после «включи»: «группу кино» ищет исполнителя).
- **Поиск музыки** — обращения, глаголы, слова перед названием, слова-исключения
  (вопросы, умный дом) и числовые настройки (`settings`).
- **JSON** — весь файл как текст, с проверкой синтаксиса.
- **Сохранить** — монитор проверяет файл самим прокси (`alice-voice-proxy --check`:
  JSON + каждый regex как его компилирует musl), при ошибке ничего не меняет и
  показывает причину; иначе заменяет файл и перезапускает прокси.
  **Сбросить по умолчанию** — копирует `voice-commands.default.json` (с
  подтверждением).

## Применить изменения

```bash
adb push voice-commands.json /data/opt/spotify-connect/voice-commands.json
adb shell 'for p in $(ps | awk "/[a]lice-voice-proxy/{print \$1}"); do kill "$p"; done; sleep 1; nohup setsid /data/opt/spotify-connect/alice-voice-proxy </dev/null >/tmp/alice-voice-proxy.out 2>&1 &'
```

Проверка: `/tmp/alice-voice-proxy.log` должен содержать
`voice-commands.json loaded: N commands, M verbs`. Если там
`NOT loaded -> using built-in command table` — JSON битый (прокси работает на
встроенной таблице, ничего не ломается), проверь синтаксис JSON.
